## Task 002 — Build the landing page

Designed and built the landing page from business-model.md. Sections: header,
hero, how-it-works, the gap-check form, footer. No pricing, as instructed.

The design direction:

- Palette is "galvanised steel and oxidised copper" — five named colours.
  Galvanise (the pale cool grey page background), Paper (slightly lighter, for
  cards), Zinc Dust (every hairline border), Millscale (the blue-black oxide on
  hot-rolled steel, used for all body text), Slate Wash (secondary text), and
  Verdigris (the single green accent, on buttons, icons and links). It reads
  industrial without being the navy-and-safety-yellow cliché, and it avoids
  both patterns you flagged.
- Type is Bricolage Grotesque for headings — tight and a bit irregular, more
  characterful than a default grotesk — over IBM Plex Sans for body copy and
  IBM Plex Mono for the small uppercase labels. Plex was drawn as a technical
  family, which suits paperwork.
- Signature detail: a tape-measure rule. A hairline with minor ticks every
  16px and a taller tick every 80px, drawn as SVG, used under the hero card and
  beside the form. It gives the page a measured, shop-drawing feel.
- No gradients, shadows, glass, or glow anywhere — separation is done entirely
  with 1px borders and background steps.

Copy notes:

- Framed around the trigger event from business-model.md: a plant tells the
  crew to get prequalified before a shutdown.
- Step 2 says out loud that a person does the comparison by hand. That's the
  truth right now, and it's a better promise than pretending there's an engine.
- Consultant cost and turnaround figures are flagged TODO-VERIFY in
  business-model.md, so the visible copy stays qualitative ("a retainer and a
  timeline that doesn't fit a shutdown window"). The reason is written into a
  code comment in the hero so it doesn't get "helpfully" filled in later.
- The three gap-check categories (written programs, training records, insurance
  documents) come straight from business-model.md and are kept at category
  level. There's a TODO-VERIFY comment above them warning against adding
  specific program names, certifications, or deadlines without a source.
- Footer states plainly that we are not affiliated with ISNetworld or Avetta and
  that a gap check is not a compliance determination. Those are other companies'
  trademarks and the disclaimer seemed necessary rather than optional.

Icons are lucide-react throughout, plus hand-written SVG for the wordmark and
the tape rule. No emoji anywhere — verified in the browser by regex over the
rendered page text.

Checked in a real browser at 1280px and 375px: no horizontal overflow at either,
both fonts loading, one h1, all form fields labelled, no console errors.

## Task 003 — Supabase lead capture

The form now writes real leads. One manual step is left over, described at the
bottom — the table itself doesn't exist yet and I couldn't create it.

What I did:

- Confirmed both Supabase values load from `.env.local` without printing them.
  The file is ignored by git and untracked; I checked both.
- Wrote `supabase/migrations/0001_leads.sql`: the `leads` table (trade,
  hiring_client, employee_count, email, created_at), RLS enabled *and* forced,
  and exactly one policy — INSERT for anon and authenticated. There is no
  SELECT, UPDATE, or DELETE policy, and under RLS anything without a matching
  policy is denied, so those are blocked. I also revoked the underlying
  select/update/delete grants, so if someone later adds a sloppy "for all"
  policy the table still won't leak. You read leads from the Supabase
  dashboard, which runs as the service role and bypasses RLS.
- Added length caps and an email-shape check as database constraints, not just
  form validation. The table is writable by anonymous callers, so it shouldn't
  depend on the form behaving.
- Server action in `src/app/actions.ts` does the insert. Validation lives in
  `src/lib/leads.ts` and runs on the server, since browser validation is a
  convenience anyone can skip by posting directly. Both dropdowns are checked
  against the allow-list rather than just tested for non-emptiness.
- Replaced the "not wired up yet" placeholder with a real success panel, plus
  field-level errors, a form-level error, a disabled pending state, and
  `aria-invalid` / `aria-describedby` wiring on the fields.
- Database errors show the visitor a generic message; the real error text goes
  only to the server log, since database errors can leak schema details.

Verified in the browser against the live project:

- Whitespace-only and malformed input get past the browser's own checks and are
  correctly rejected by the server, with the right message on the right field.
- A failed submission comes back with everything still filled in.
- A valid submission currently hits the missing table and shows the generic
  failure message, with the real cause ("Could not find the table
  'public.leads'") appearing only in the server log. That confirms the
  credentials work — a bad key returns 401, not a missing-table error.
- The success panel renders correctly.

Two things worth knowing:

- `npm run build` passed while the app was actually broken at runtime: I had
  exported the initial state object from the `"use server"` file, which is only
  allowed to export async functions. It only showed up when I loaded the page.
  Moved the state type and initial value into `src/lib/leads.ts`. Worth
  remembering that a green build doesn't mean a server action works.
- Selects weren't being repopulated after a failed submission — React only
  reads `defaultValue` when a field first mounts, so the dropdowns sat back on
  their placeholder even though the server sent the values back. Fixed by
  keying each field on its echoed value so it remounts. Caught this by testing;
  it would have been an easy one to ship.

Decisions made without asking:

- Used the publishable key rather than a service-role key. With insert-only
  RLS the anon role is enough, and a service-role key on the server would be a
  far bigger thing to leak for no benefit here.
- Verified the success panel by temporarily short-circuiting the action behind
  an env flag, then removed both the flag and the code. Neither is in the
  commit — I checked.
- Branched task/003 off task/004-seo and merged task/002 into it, so this
  branch has everything: scaffold, page, wordmark fix, SEO. Merge order for
  review is 001, 002, 004, 003.
