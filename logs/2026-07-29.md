# Task 062 — requests page states, and a navigation indicator for the app

## What was wrong

The requests page had no `loading.tsx` of its own, so it fell through to the
one at `/dashboard`. That file was written when the dashboard was a list and a
submission detail page; it is now the fallback for Requests, Documents,
Programs, Company and Help as well, and it said "Opening your file…" to all of
them. In the gap the workspace chrome stayed put and the content area went
empty, which reads less like loading than like a page that broke.

Underneath that was a worse one. `listRequestsForEmail` caught a failed query,
logged a warning and returned an empty array. An outage therefore rendered as
"No requests yet" — a calm, confident, wrong answer, and about the most
alarming thing this product could say to somebody with work in flight. The page
could not have had an error state, because nothing ever reached one.

## What changed

**The four states of the requests page.** A skeleton while it loads, matched to
the real row height so nothing moves when the content lands; the existing empty
state; a new error state with a Try again button; and the populated list. All
four share one header block, so the title sits in the same place in each and
the page does not jump between them. Measured in the browser: h1 at the same x
in all four, rows 87px in both the skeleton and the real list, lists 285px.
The first attempt was 7px short per row — eyeballed heights instead of the
line boxes of the text they stand for — which is a full row of shift on
arrival and precisely what a skeleton exists to prevent.

**A store variant that fails loudly.** `listRequestsForEmailOrThrow` throws
where the old function swallowed, and the requests page uses it so a failure
reaches `error.tsx`. The tolerant version stays for the overview and help
pages, where the list is a panel beside other things and taking the whole page
down over it would be the wrong trade. A failed *events* query now throws too:
state is derived from the events, so a request whose log failed to load does
not render as unknown, it renders with whatever `deriveStatus` makes of an
empty list — every row mislabelled and none of them looking it.

**A route transition bar.** Two pixels of verdigris at the top of the page, in
the root layout, for every navigation in the app. Nothing appears for the first
200ms so a prefetched route never flashes one. The fill is a single transform
transition to 90% over eight seconds on a steep ease-out: quick while the wait
is plausibly nearly over, then visibly crawling, and never arriving before the
page does. Sampled through the Web Animations API: 28% at 250ms, 51% at 1s,
82% at 4s.

The App Router publishes no "navigation started" event — `usePathname` changes
when the new route commits, which is the end of the wait — so the start signal
is the click. `lib/nav-intent.ts` decides which clicks are going somewhere and
is the part with tests, all but two of them negative. The failure that matters
is not a missing bar, it is a bar that starts for a click that was never going
to navigate and then has nothing to finish it: a download, a `mailto`, a
`#` jump, a middle click, an external link. All six were fired at the live page
and none started anything. There is an eight second backstop besides.

## Also

`/dashboard/[id]/loading.tsx` now carries the "Opening your file…" copy, which
is the one route it describes, and `/dashboard/loading.tsx` says "Loading…".
Both lost an `mx-auto max-w-4xl px-6` that predated the workspace chrome and
sat on top of the layout's own centred column, indenting the spinner further
than the content it stood in for — the page stepped sideways when it loaded.

## Not verified

No screenshots. The browser pane was not displayed this session, so it reported
`document.visibilityState: "hidden"` and did not composite frames or advance
CSS transitions — an isolated control div with inline styles would not
interpolate either. Everything above was checked through the DOM, the computed
stylesheet and the Web Animations API instead. The bar has not been watched
moving by a person.
